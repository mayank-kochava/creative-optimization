# Implementation Plan: Creative Intelligence Platform

**PRD:** [product-spec-v2.md](./product-spec-v2.md)  
**Research:** [eng-research.md](./eng-research.md)  
**Date:** 2026-05-14  
**Status:** Draft  
**Timeline:** 7 days (2026-05-14 → 2026-05-21)

## Summary

Building a greenfield Creative Intelligence Platform: a Python/FastAPI backend with Qwen2-VL-7B vision analysis via Ollama, PostgreSQL storage, and a React/Next.js frontend. The platform ingests ad creatives, scores them across 7 dimensions, detects duplicates via pHash, and flags fatiguing creatives by WoW CTR trend. All inference runs locally — no external APIs. Demo uses pre-seeded data from CVPR 2017 corpus.

### Phase 2a: Analysis Engine + Deduplication (Day 2 — 8h)

**Goal:** Core creative analysis and duplicate detection working  
**Prerequisites:** Phase 1

- [ ] `backend/app/modules/analysis/provider.py` — `AnalysisProvider` abstract base class with `analyse(image_path) -> AnalysisResult`
- [ ] `backend/app/modules/analysis/schemas.py` — Pydantic v2 `AnalysisResult` model (7 scores, persuasion_strategy, emotion, strengths, weaknesses, recommendations, explanation, status)
- [ ] `backend/app/modules/analysis/prompt.py` — structured JSON prompt with 3 few-shot examples from A³ dataset; `respond ONLY with valid JSON` constraint
- [ ] `backend/app/modules/analysis/ollama.py` — `OllamaProvider(AnalysisProvider)`: base64 encode → POST to `qwen2.5vl:7b` → Pydantic validate → retry (3x, temp=0) → degraded on 3rd failure; pre-warm on init
- [ ] `backend/app/modules/deduplication/service.py` — `compute_phash(path) -> int`, `find_duplicates(phash, campaign_id) -> List[DuplicateMatch]` with advisory lock + serialisable transaction
- [ ] Unit tests: `tests/unit/test_deduplication.py` — same image → 0, resized → ≤10, different → >10, concurrent inserts → single record
- [ ] Unit tests: `tests/unit/test_analysis_engine.py` — mock Ollama via respx; valid JSON → AnalysisResult; malformed JSON → retry; 3 failures → degraded status

**Deliverables:** `POST /campaigns/{id}/creatives` returns analysis result with 7 scores; duplicate detection flags near-matches

### Phase 2b: Video + Annotation + Benchmark + Fatigue (Day 3 — 8h)

**Goal:** All remaining backend features complete; seed data pre-computed  
**Prerequisites:** Phase 2a

- [ ] `backend/app/modules/fatigue/service.py` — `compute_fatigue(creative_id) -> FatigueResult`: min 7 days check → insufficient_data; WoW calc; threshold 20%
- [ ] Background job (APScheduler or FastAPI lifespan): run fatigue detection daily on all creatives
- [ ] `backend/scripts/precompute_demo.py` — run full analysis on all 50 seed creatives, cache results in DB, log timing
- [ ] Unit tests: `tests/unit/test_fatigue.py` — >20% WoW → fatiguing; flat → healthy; <7 days → insufficient_data

## Risks & Mitigations

| Risk | Probability | Impact | Mitigation |
|---|---|---|---|
| Qwen2-VL produces inconsistent JSON structure | M | H | Pydantic schema + 3-retry + degraded fallback (Phase 2a) |
| 11.6GB CVPR download takes > 6h | M | M | 500-image fallback corpus bundled in repo; full corpus async |
| M4 Pro OOM during demo (Chrome + Slack + model) | M | H | Pre-demo checklist: 12GB free RAM; quit non-essential apps |
| Tesseract not installed in Docker image | L | M | Use `tesseract` base image; verify in Day 1 Docker setup |
| Video pre-compute takes > 2h for 10 videos | L | M | Limit seed data to 3 video creatives; rest are images |
| Annotation pipeline slow on M4 (> 500ms) | L | L | Cap annotation at 10 regions; skip if > 1s |
| ffmpeg-python install fails on M4 | L | M | Fallback to subprocess; test on Day 3 before committing |
